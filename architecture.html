Factory Inventory Management System

System architecture, tech stack, and data flow reference

Demo Application
Overview

A full-stack demo application for tracking factory inventory, orders, demand forecasting, backlog, and spending analytics. The frontend is a Vue 3 SPA communicating with a Python FastAPI backend over HTTP. All data is stored as JSON files and loaded into memory at server startup — there is no database. A global filter bar (warehouse, category, order status, time period) passes query parameters to every API call, with server-side filtering applied before returning Pydantic-validated responses.

Key Design Decisions
Filter Pattern

All filters default to 'all', which the backend skips entirely. This keeps every endpoint stateless and idempotent. Filtering is case-insensitive and applied sequentially on in-memory copies — the global list is never mutated.

Reactivity Model

Raw API data lives in ref(). All derived display values (totals, filtered lists, chart points) are computed(), keeping them cached and automatically invalidated when upstream refs change. The useFilters composable is a module-level singleton shared across views.

No Database

Data is loaded from JSON files into Python lists at startup via mock_data.py. Changes (tasks, purchase orders) are in-memory only and reset on server restart. Adding a real database would require replacing mock_data.py and adding async DB queries.
